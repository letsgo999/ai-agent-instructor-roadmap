AI 에이전트 실무 활용 강사과정
남은 4주 학습 로드맵

AI를 쓰는 사람에서
AI 팀을 설계하는 사람으로

Hermes를 중심으로 Claude와 Codex를 전문 팀원처럼 결합해, 사람이 하던 업무를 분석하고 여러 에이전트가 협업·검수·인계하는 실무 시스템으로 전환합니다.

과정의 핵심 목표
“사람이 하던 업무를 AI 팀이 수행할 수 있도록 설계·지휘·검수하는 사람”을 만든다.

01 · Direction

도구 설명이 아니라 업무 전환을 배웁니다

STEP 1업무 분석
STEP 2팀 설계
STEP 3협업·검수
STEP 4자동화
STEP 5검증·인계

업종별로 서로 다른 사례를 암기하지 않습니다. 모든 조직에 공통으로 존재하는 업무 유형과 전환 절차를 익힌 뒤, 참가자 각자의 현장 과제에 적용합니다.

02 · Roadmap

남은 4주의 발전 순서

2주차

업무를 에이전트가 수행 가능한 구조로 바꾸기

  • 좋은 자동화 대상과 나쁜 자동화 대상 구별
  • 시작 조건·입력·처리·결과·완료 기준 정의
  • 한 사람의 업무를 여러 역할로 분해
  • 에이전트별 권한과 금지 행동 설정
  • 사람이 반드시 승인해야 하는 지점 설정
  • 업무 유형별 과제 분류
남는 결과물
기존·전환 업무 흐름, 에이전트 역할표, 입출력 기준, 사람 승인 지점, 실패·복구 규칙
핵심 질문: “어떤 상태가 되면 이 업무가 끝난 것인가?”
3주차

여러 에이전트를 실제 팀처럼 운영하기

  • 단일 에이전트와 복수 에이전트의 차이
  • 업무 분할과 역할 중복 방지
  • 에이전트 간 업무 요청과 결과 인계
  • 대기·진행·검수·완료·실패 상태 관리
  • 독립 검수자가 필요한 상황
  • 잘못된 반복과 응답 순환 방지
남는 결과물
에이전트 팀 1차 버전, 역할 카드, 인계 규칙, 검수 항목, 동일 업무 2회 실행 기록
상호검수: 처음 보는 동료가 설명만 보고 실행하고 오류를 발견할 수 있는가?
4주차

실제 업무에 연결하고 반복 실행하기

  • 일회성 대화와 반복 가능한 시스템의 차이
  • 파일·웹·문서·데이터 등 외부 자원 연결
  • 수동·반자동·자동 실행의 구분
  • 오류 재시도 횟수와 중단 기준
  • 실행 기록과 결과 증거 남기기
  • 개인정보·기밀·외부 발신 관리
남는 결과물
에이전트 팀 2차 버전, 실행 조건, 승인 단계, 실패·중단 규칙, 실행 기록, 운영 설명서
권장 순서: 수동으로 정확히 실행 → 반자동으로 안정화 → 필요한 부분만 자동화
5주차

현장 시스템으로 완성하고 검증하기

  • 현장 과제를 처음부터 끝까지 실제 실행
  • 결과 품질과 업무시간 절감 가능성 평가
  • 다른 참가자가 대신 실행하는 교차시험
  • 오류와 불필요한 에이전트 제거
  • 현업 도입 시 담당자·승인자·검수자 설정
  • 희망자 5~10분 설명·시연
남는 결과물
업무 정의서, 에이전트 조직도, 실행 흐름, 검수·승인 규칙, 인계 가능한 운영 안내서
완료 기준: 내가 만든 시스템을 다른 사람이 이어받아 반복 실행할 수 있는가?
03 · Roles

도구는 기능이 아니라 역할로 배정합니다

Hermes

업무 접수, 분배, 진행 상태 관리, 도구 실행과 결과 취합을 맡습니다.

Claude

긴 문서 분석, 맥락 이해, 기획, 설명과 초안 작성에 활용합니다.

Codex

코드, 스크립트, 데이터 처리, 파일 작업과 기술적 검증을 수행합니다.

사람

목표·권한·예외를 결정하고, 민감정보를 판단하며 최종 결과를 승인합니다.

역할을 고정 공식으로 외우지 않습니다. 먼저 업무에 필요한 역할을 설계한 뒤 그 역할에 가장 적합한 도구를 배정합니다.

04 · Common Standard

업종이 달라도 같은 기준으로 실습합니다

  1. 업무 하나 선택
  2. 현재 사람이 하는 절차 기록
  3. 입력과 최종 결과 정의
  4. 완료·합격 기준 작성
  5. 업무를 역할 단위로 분해
  6. 필요한 에이전트 설계
  7. Hermes·Claude·Codex에 역할 배정
  8. 사람 승인 지점 설정
  9. 실제 실행
  10. 동료 교차검수
  11. 같은 업무 재실행
  12. 실패·수정·재실행 기록
  13. 인계 가능한 형태로 정리
05 · Checklist

좋은 현장 과제를 고르는 기준

추천하는 과제

  • 반복적으로 발생한다
  • 시작 조건이 분명하다
  • 입력 자료를 구할 수 있다
  • 기대 결과의 형태가 분명하다
  • 결과의 좋고 나쁨을 판단할 수 있다
  • 여러 단계나 역할로 나눌 수 있다
  • 잘못됐을 때 사람이 발견할 수 있다
  • 수업 중 시험할 수 있을 만큼 작다
  • 시간 절감이나 품질 향상 가치가 있다
  • 개인정보·기밀을 제거할 수 있다

초반에 피할 과제

  • 계약·법률·인사평가·자금 집행을 자동 결정
  • 개인정보나 회사 기밀이 그대로 포함
  • 정답이나 품질 기준을 정할 수 없음
  • 한 번 실행하는 데 며칠이 걸림
  • 기존 절차를 참가자 본인도 설명하지 못함
  • 사람 확인 없이 외부 고객에게 바로 발송
  • 처음부터 완전자동화를 요구함
06 · Outcome

수료할 때 남아야 할 다섯 가지

01. 업무 정의서

무엇을, 왜, 언제 시작해 어떤 결과로 끝낼지 설명합니다.

02. 에이전트 조직도

각 역할과 책임, 권한, 금지 행동을 구분합니다.

03. 실행 가능한 흐름

실제 입력부터 결과 생성까지 반복할 수 있습니다.

04. 검수·승인 규칙

오류 발견, 사람 승인, 실패 중단과 복구 기준을 둡니다.

05. 운영 안내서

다른 사람이 이어받아 실행할 수 있도록 기록합니다.

최종 평가 질문

평가 항목확인 질문
실무 적합성실제 업무에서 사용할 가치가 있는가?
반복 가능성같은 조건으로 다시 실행할 수 있는가?
역할 명확성각 에이전트가 맡은 일이 분명한가?
결과 품질정해진 완료 기준을 충족하는가?

안전성권한·기밀·외부 발신이 통제되는가?

07 · Principles

수업 운영의 다섯 가지 원칙

1. 기능 설명은 필요할 때만 합니다
Hermes의 기능을 먼저 전부 설명하지 않습니다. 참가자가 자기 업무를 수행하는 과정에서 필요한 기능을 그때 소개합니다.
2. Claude와 Codex를 별도 과목처럼 가르치지 않습니다
매주 하나의 업무 흐름 안에서 세 도구가 어떤 역할을 맡는지 경험하게 합니다. 도구보다 업무와 역할이 먼저입니다.
3. 에이전트 수를 성과로 평가하지 않습니다
에이전트가 많다고 좋은 시스템은 아닙니다. 역할이 중복되거나 인계 비용이 커지면 오히려 단일 에이전트보다 비효율적입니다.
4. 성공보다 실패 수정 과정을 평가합니다
첫 실행의 성공 여부보다 실패 원인을 찾고, 역할이나 지시를 수정하고, 다시 실행해 결과가 나아졌는지를 봅니다.
5. ‘사람 대체’보다 ‘업무 역할 대행’으로 설명합니다
사람이 맡던 반복 가능한 일부 역할을 에이전트가 수행하고, 사람은 목표·권한·예외·최종 결정을 담당합니다.

4주를 한 문장씩 정리하면

  1. 2주차: 내 업무를 에이전트가 수행할 수 있도록 구조화한다.
  2. 3주차: 여러 에이전트가 협업하고 서로 검수하도록 만든다.
  3. 4주차: 실제 도구와 업무에 연결하여 안전하게 반복 실행한다.
  4. 5주차: 다른 사람도 사용할 수 있는 현장 시스템으로 완성한다.
